# 简介

MeshStream 是面向视频、直播和音频业务的 P2P 媒体加速平台。它以 SDK 的形式接入现有播放链路，在不替换播放器、源站和 CDN 的前提下，为可复用的媒体分片提供额外的传输路径。

## 产品定位

热点内容会在短时间内产生大量相同的媒体请求。MeshStream 允许符合策略和网络条件的观看设备复用已获取的媒体分片，从而降低热点内容对 CDN 带宽的集中压力。P2P 是可控的增强路径，CDN 始终保留为稳定的播放路径。

MeshStream 不改变业务应用对播放器、源站、DRM 或 CDN 的既有所有权和控制边界：播放器继续负责清单解析、ABR、解码和渲染；源站继续负责媒体授权；CDN 继续提供完整的可用性保障。

## 播放会话模型

![接入流程](/img/flow-connect.svg)

每次播放都应创建一个独立的会话，标准流程如下：

1. 业务应用将原始媒体地址和 SDK Key 交给 SDK；
2. SDK 创建播放会话，并返回本次会话对应的播放地址；
3. 业务播放器加载 SDK 返回的播放地址，继续执行原有播放流程；
4. 会话结束、切换内容或页面销毁时，业务应用释放该会话。

SDK 会根据内容标识、网络条件和服务策略选择可用的传输路径。加速能力暂不可用时，播放器仍可通过原有 CDN 路径继续播放。

## 接入边界

- **播放器保持不变**：SDK 不接管 ABR、解码、渲染或 DRM。播放器必须继续支持业务使用的媒体格式。
- **跨平台统一**：同一应用可接入 Web、Android、iOS 和 Windows SDK，使用统一的 Key、内容标识和统计口径。
- **媒体格式**：HLS 和 DASH 由业务播放器负责解析；MP4、MP3 直链是否启用加速，取决于平台能力、Service Worker（Web）和源站 Range 支持。
- **鉴权责任清晰**：签名 URL、Cookie、Authorization、源站请求头和 DRM 仍由业务方的媒体服务负责。源站凭证不会发送给其他观看设备。
- **故障隔离**：配置、网络或加速连接异常不应阻断播放器。业务代码不应把“加速不可用”当作“媒体不可播放”处理。

## 统计与用量

SDK 在播放过程中异步记录会话状态、P2P 传输、CDN 传输、Peer 数量和异常原因，并在控制台按应用、Key、平台和内容维度聚合展示。

MeshStream 的额度仅按实际产生的 P2P 下载流量计算。未命中 P2P 时，播放仍可使用业务方 CDN；相关 CDN 传输数据用于效果分析和故障诊断，不计入 MeshStream 的 P2P 额度。

## 适用场景

- 直播、点播、赛事和大型活动等具有明显重复观看特征的内容；
- 需要降低热点内容 CDN 峰值带宽或缓解源站压力的业务；
- 希望在保留现有播放器和 CDN 的基础上，以灰度方式引入 P2P 能力的团队。
