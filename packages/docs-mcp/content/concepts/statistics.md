# 统计与用量

SDK 在播放过程中异步上报运行数据，在用户控制台按应用、Key 和平台聚合展示。上报是后台链路，失败不会影响播放。

## 上报维度

- **应用与 Key**：用量归属到具体应用和 Key，便于按业务或平台拆分。
- **平台**：Web / Android / Windows / iOS。

## 主要指标

| 指标 | 含义 |
| --- | --- |
| Peer 数 | 当前播放会话连接的其他设备数 |
| P2P 下载流量 | 经 P2P 分发的字节量，也是 MeshStream 的计费流量 |
| CDN 回源流量 | P2P 未命中时从客户 CDN 获取的字节量，仅用于效果和故障分析，不扣 MeshStream 额度 |
| P2P 上传贡献 | 当前设备向其他设备分享的字节量，不收费 |
| 命中率 | P2P 下载流量占 P2P 下载流量与 CDN 回源流量之和的比例 |
| 会话数 | 完成或活跃的播放会话数量 |

## CDN 分流率的计算与验证 {#offload-rate}

CDN 分流率按实际下载字节计算：

```text
CDN 分流率 = P2P 下载流量 /（P2P 下载流量 + CDN 回源流量）× 100%
```

分流率不设固定承诺值，应以业务的实际统计结果为准。结果取决于同一内容的并发量、用户播放进度、用户之间的网络可达性、地域分布、媒体格式、分片时长和缓存策略。

验证时应使用相同应用和播放地址，启动多台真实设备持续播放，并分别记录 P2P 下载流量和 CDN 回源流量。直播与点播需要分开统计；预热阶段、异常退出和仅有单个观看用户的时段不应与稳定并发阶段混为一组。建议同时记录测试时间、设备数量、平台、区域、媒体协议和分片时长，确保不同轮次可以复现和比较。

## 查看方式

在用户控制台的用量与会话页面按时间范围和平台筛选。新会话数据通常在播放结束并调用 `dispose` 后完成上报；播放过程中即可看到实时活跃会话。

## 注意事项

- 播放结束后务必调用 `dispose` / `close`，未释放的会话不会生成完整统计。
- 统计由 SDK 在后台异步完成，业务代码只需在播放结束时正确释放会话。
